## Correction 1: Parameter Count

**CLAIM AS WRITTEN:** "6 tunable parameters"
**CORRECTED TO:** "8 tunable parameters"
**RATIONALE:** Code implements 8 parameters: conflict_sensitivity (float), semantic_threshold (float), exploration_budget (int), cross_path_detection (bool), ai_default_arc (CompositionArc IntEnum), red_team_threshold (int), payload_surfacing (bool), cascade_auto_challenge (bool). All 8 are exposed via cb_tune_parameters.

## Correction 2: semantic_threshold Range

**CLAIM AS WRITTEN:** "semantic_threshold in range [0.0, 1.0]"
**CORRECTED TO:** "semantic_threshold in range [0.5, 0.99]"
**RATIONALE:** Values below 0.5 produce excessive noise in semantic matching. A value of 1.0 would require exact embedding match, which is unreachable in practice. The [0.5, 0.99] range represents the functional operating envelope.

## Correction 3: red_team_threshold Range

**CLAIM AS WRITTEN:** "red_team_threshold in range [0, 100]"
**CORRECTED TO:** "red_team_threshold in range [3, 20]"
**RATIONALE:** Values below 3 trigger on noise (false positives). Values above 20 effectively disable red-teaming. The [3, 20] range bounds the useful operating region.

## Correction 4: arc Priority — Discrete Enum, Not Continuous

**CLAIM AS WRITTEN:** "arc priority in continuous range [1, 100]"
**CORRECTED TO:** "arc priority as discrete IntEnum: LOCAL=10, INHERITS=20, VARIANT_SET=30, REFERENCES=40, PAYLOADS=50, SPECIALIZES=60"
**RATIONALE:** Arc priority levels map directly to USD composition arc precedence (LIVRPS ordering). Discrete levels enforce valid composition semantics. Arbitrary values between levels have no meaningful interpretation.

## Correction 6: SQLite Storage Path

**CLAIM AS WRITTEN:** "~/.cognitive_bridge/"
**CORRECTED TO:** "~/.cognitive_bridge/projects/cognitive_bridge.db"
**RATIONALE:** The /projects/ subdirectory provides namespace isolation. A single cognitive_bridge.db file contains all projects, with each table using an indexed project_id column for multi-project isolation within the same database. The directory is overridable via the CB_DB_DIR environment variable.

## Correction 7: state_history Implementation

**CLAIM AS WRITTEN:** "state_history field on Assertion model"
**CORRECTED TO:** "Lifecycle history derived from append-only Event log via get_events_for_target()"
**RATIONALE:** Rather than a denormalized state_history field, lifecycle transitions are recorded as immutable Event objects (17 event types) in an append-only audit log. The get_events_for_target() function retrieves the ordered lifecycle sequence. This provides richer provenance (actor, timestamp, detail dict) than a simple state list.

## Correction 8: Variant Field Name

**CLAIM AS WRITTEN:** "activation_weight (float)"
**CORRECTED TO:** "activation_condition (Optional[str])"
**RATIONALE:** Variant activation is condition-based (a string expression), not a numeric weight. String conditions allow richer activation logic (e.g., "when database choice is finalized") than a float threshold.
