## The Four Detection Layers

### Layer 1: Structural (Your highest priority)
- **Trigger:** New assertion at a topic_path that already has an active assertion with different content
- **Cost:** O(1) dict lookup. Must run on EVERY assertion insert.
- **Logic:** Same path + different content = automatic conflict. Same content = reinforcement (not conflict).
- **Output:** A `Conflict` object with `detection_layer=STRUCTURAL`

### Layer 2: Semantic
- **Trigger:** New assertion inserted. Check embedding similarity against all active assertions on DIFFERENT paths.
- **Dependency:** Requires `sentence-transformers` (all-MiniLM-L6-v2). Loaded at server lifespan.
- **Logic:** Compute embedding for new assertion. Cosine similarity against all existing embeddings. If similarity >= threshold AND paths differ → semantic warning.
- **Output:** List of warning dicts (not confirmed conflicts). The tool surfaces these for Claude to evaluate.
- **Gate:** Only runs if `parameters.cross_path_detection == True`

### Layer 3: Delegated (The Boomerang)
- **This is NOT code you write.** It's a response formatting pattern.
- Layer 2 warnings are formatted into the tool response text. Claude reads them, evaluates whether they're real conflicts, and calls `cb_manage_conflict(action="create")` if so.
- Your job: ensure Layer 2 warnings include enough context for Claude to judge (assertion ID, path, content, similarity score).

### Layer 4: Cascading (The DAG Compiler)
- **Trigger:** The winning assertion at a topic_path changes (new assertion overrides, promotion, retraction).
- **Logic:** Call `stage.get_dependents(changed_path)`. For each dependent:
  1. Mark `assumption_status = CHALLENGED`
  2. Create a `Conflict` with `detection_layer=CASCADING`
  3. Log events: `ASSERTION_CHALLENGED` for each dependent
- **Falsification:** When `check_falsification()` is called, mark the assertion as `FALSIFIED`, then cascade to all dependents with `assumption_status = ORPHANED`.
- **Output:** List of `Conflict` objects with `cascade_source_path` set.

## Resolution Engine

### LIVRPS Resolution
- For each topic_path, sort active assertions using `Assertion.__lt__` (arc → confidence → recency)
- The first in sorted order is the "winner"
- All others form the "shadow stack" (preserved, not deleted)
- Detect "unstable ties" — top two assertions on the same arc need negotiation

### Winner Change Detection
Critical for triggering Layer 4:
```python
old_winner = get_current_winner(stage, path)
# ... insert/promote/retract ...
new_winner = get_current_winner(stage, path)
if old_winner and new_winner and old_winner.id != new_winner.id:
    cascading_conflicts = detect_cascading_conflicts(stage, path, new_winner.id)
```

## Design Principles

### Pure Functions Where Possible
Detection functions take a stage + assertion and return conflicts. They don't modify the stage directly. The tool layer handles mutations.

Exception: `cascade.py` modifies `assumption_status` on assertions because this is a side effect of detection. Document this clearly.

### Embeddings
- Generated by `sentence-transformers/all-MiniLM-L6-v2` (22M params, ~5ms per encoding)
- Stored on the Assertion model as `embedding: Optional[List[float]]`
- Lazy computation: only generate embedding when cross_path_detection is enabled
- Cosine similarity: `np.dot(a, b) / (norm(a) * norm(b))`

### Provenance
- Every detection → `EventType.CONFLICT_DETECTED` event
- Every cascade → `EventType.ASSERTION_CHALLENGED` event per dependent
- Every falsification → `EventType.ASSERTION_FALSIFIED` + `ASSERTION_ORPHANED` per dependent
- Events are append-only. Never modify or delete.

## Testing Requirements

- `test_structural_detection.py`: same path different content → conflict. Same content → no conflict. Different paths → no conflict.
- `test_cascade.py`: linear chain A→B→C, change A → B and C challenged. Diamond: A→B, A→C, B→D, C→D, change A → all challenged. Falsification: mark A falsified → dependents orphaned.
- `test_semantic_detection.py`: high similarity across paths → warning. Low similarity → no warning. Same path → skip (handled by Layer 1). Cross-path disabled → skip.
- `test_resolver.py`: single assertion → wins. Multiple arcs → lowest IntEnum wins. Tie on arc → highest confidence wins. Tie on both → most recent wins.
