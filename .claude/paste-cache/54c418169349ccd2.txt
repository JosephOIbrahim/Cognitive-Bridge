### Technical Constraints (Memorize These)
1. **ComfyUI uses aiohttp, NOT FastAPI** — routes mount on `PromptServer.instance.routes`
2. **JS imports are relative** — `import { app } from '../../scripts/app.js'`
3. **Agent brain is Python, imported directly** — no HTTP between UI backend and brain
4. **`WEB_DIRECTORY = "./web"`** — tells ComfyUI to serve `ui/web/` as static assets
5. **Sidebar API requires ComfyUI frontend ≥ v1.2.4** — `registerSidebarTab`

## Phase 2: Backend Bridge
**Department:** `/COMFY_LEAD` — Lead Technical Director
**Duration:** 1-2 hours
**Deliverable:** Round-trip chat — user types, agent brain responds through sidebar
**Depends on:** Phase 1 sidebar skeleton

### DISPATCH PROMPT:
```
/COMFY_LEAD

SHOW: SUPER DUPER UI — Phase 2: Backend Bridge
You are the Lead TD. You know ComfyUI's internals — PromptServer, aiohttp,
the WebSocket protocol, /object_info, /queue, /history, the whole API surface.

CONTEXT: Read SUPERDUPER_UI_PLAN_v2.md. Read the Phase 1 handoff report
(it tells you what exists and what needs wiring).

YOUR DELIVERABLE: The sidebar sends a message → agent brain processes it →
response appears in sidebar. Real data, not echoes.

CRITICAL CONSTRAINT: ComfyUI uses aiohttp. Do NOT import FastAPI.
Routes mount on PromptServer.instance.routes. This is non-negotiable.

TASKS:

1. MOUNT SERVER ROUTES (ui/server/routes.py)
   Mount on ComfyUI's PromptServer:
   - POST /superduper/chat — receive user message, return agent response
   - GET /superduper/status — current agent/execution state
   
   Import pattern:
   ```python
   from server import PromptServer  # ComfyUI's module
   from aiohttp import web
   
   routes = PromptServer.instance.routes
   
   @routes.post('/superduper/chat')
   async def handle_chat(request):
       data = await request.json()
       user_message = data.get('content', '')
       # Route to agent brain — import from agent/
       # Return: {"role": "agent", "content": "...", "stage": "UNDERSTAND"}
   ```
   
   The agent brain lives in agent/. Study agent/main.py and agent/tools/
   to understand how to invoke it programmatically (not via CLI).
   You may need to create a thin adapter if the brain only has a CLI entry point.

2. CREATE WEBSOCKET BRIDGE (ui/server/ws_bridge.py)
   Bidirectional WebSocket for real-time updates:
   
   Client → Server protocol:
   - {"type": "chat", "content": "make it dreamier"}
   - {"type": "approve", "patch_id": "abc123"}
   - {"type": "reject", "patch_id": "abc123"}
   
   Server → Client protocol:
   - {"type": "message", "role": "agent", "content": "..."}
   - {"type": "stage", "stage": "DISCOVER", "detail": "Searching for glow nodes..."}
   - {"type": "progress", "percent": 45, "node": "KSampler"}
   - {"type": "result", "image_url": "/view?filename=..."}
   - {"type": "error", "message": "..."}
   
   Mount WebSocket endpoint:
   ```python
   @routes.get('/superduper/ws')
   async def websocket_handler(request):
       ws = web.WebSocketResponse()
       await ws.prepare(request)
       # ... handle messages
   ```
   
   Key decisions:
   - Tap into ComfyUI's existing WS for generation progress events
   - Forward progress to sidebar client
   - Agent brain calls MUST be async — don't block the event loop
   - If brain is synchronous, wrap in asyncio.to_thread()

3. WIRE ROUTE MOUNTING INTO ui/__init__.py
   The routes need to be mounted when ComfyUI loads the custom node.
   Update ui/__init__.py to import and register the server routes.
   
   Pattern (check how other custom nodes with server routes do this):
   ```python
   from .server.routes import setup_routes
   setup_routes()  # Called at import time
   ```

4. UPDATE SIDEBAR JS (ui/web/js/sidebar.js)
   Replace the "(not connected yet)" echo with actual WebSocket connection:
   - Connect to ws://localhost:8188/superduper/ws on sidebar load
   - Send {"type": "chat", "content": text} on user input
   - Parse incoming JSON messages and render by type:
     * "message" → show in chat area
     * "stage" → show stage indicator (UNDERSTAND/DISCOVER/PILOT/VERIFY)
     * "progress" → show progress bar
     * "error" → show in red
   - Handle reconnection if WebSocket drops
   - Show connection status indicator

5. TEST END-TO-END
   ```
   1. Restart ComfyUI (loads new routes)
   2. Open sidebar
   3. Type "what nodes do I have for upscaling?"
   4. Agent should query /object_info, filter, respond in sidebar
   5. Type "describe this workflow" (with one loaded in ComfyUI)
   6. Agent should use UNDERSTAND layer, respond with description
   ```

6. PHASE REPORT
   ```

   Agent brain adapter: [how the brain is invoked — direct import / adapter class / etc.]

## Phase 5: Multi-Workflow Chaining
**Department:** `/VFX_SUPER` (architecture) + `/COMFY_LEAD` (implementation)
**Duration:** 2-4 hours
**Deliverable:** Multi-step pipeline from single conversational prompt
**Depends on:** Phase 4 complete + Phase A from comfyui-agent-next-phase.md

### PRE-REQUISITE CHECK
Phase 5 requires the PILOT layer to support multi-workflow chaining
(output of workflow A feeds into workflow B). This is Phase A from
`comfyui-agent-next-phase.md`. If Phase A hasn't shipped yet, STOP HERE
and ship Phase A first.

### DISPATCH PROMPT — Architecture (VFX_SUPER):
```
/VFX_SUPER

SHOW: SUPER DUPER UI — Phase 5 Architecture Review
You are the VFX Supervisor. Creative and technical authority.

Before /COMFY_LEAD implements multi-workflow chaining in the UI, you need
to sign off on the pipeline architecture. This is comp pipeline thinking —
you've done this in Nuke for years.

REVIEW:

1. PIPELINE TOPOLOGY
   A multi-stage pipeline looks like:
   txt2img → img2img_refine → upscale → glow_post
   
   Or for 3D:
   txt2mesh → texture_apply → UV_unwrap → render_preview
   
   Questions to answer:
   - Is each stage a separate ComfyUI prompt execution? Or one big graph?
   - If separate: how are file references passed between stages?
   - If one graph: how does the agent compose multiple workflow templates?
   - What happens when Stage 2 fails? Retry Stage 2 only? Start over?

2. STATE MANAGEMENT
   The sidebar needs to track:
   - Overall pipeline: 3 of 5 stages complete
   - Per-stage state: pending / running / complete / failed / skipped
   - Intermediate outputs: images/meshes at each stage
   - User can re-run individual stages without restarting the whole pipeline
   
   Where does this state live? In the WebSocket bridge? In the agent brain?
   In a new pipeline_state module?

3. ERROR RECOVERY
   In a Nuke comp, if one node fails, you fix it and re-render from there.
   Same principle here:
   - Stage 3 fails → show error → user fixes → re-run Stage 3 only
   - Stage 3 output is wrong → user says "redo this part" → agent re-runs
   - Must NOT re-run Stages 1-2 if their outputs are still valid

4. DELIVERABLE
   Architecture Decision Record:
   - Pipeline topology: [separate prompts / single graph / hybrid]
   - State management: [where, schema]  
   - Error recovery: [strategy]
   - File passing: [how outputs flow between stages]
   
   Then greenlight /COMFY_LEAD to implement.
```

3. PIPELINE CONTROLS
   - [⏸️ Pause] — stop after current stage completes

   If Hunyuan3D nodes are installed, also test:

   2. Agent plans: txt2mesh → texture → render

## Cross-Phase Reference

### WebSocket Protocol (Complete)
All phases contribute to the WebSocket protocol. Here's the complete spec:

```
Client → Server:
  {"type": "chat",    "content": "..."}
  {"type": "approve", "patch_id": "..."}
  {"type": "reject",  "patch_id": "...", "reason": "optional"}
  {"type": "pipeline_control", "action": "pause|skip|retry|cancel", "stage": N}

Server → Client:
  {"type": "message",  "role": "agent", "content": "..."}
  {"type": "stage",    "stage": "UNDERSTAND|DISCOVER|PILOT|VERIFY", "detail": "..."}
  {"type": "discover", "results": [{name, description, installed, source, url}]}
  {"type": "diff",     "patch_id": "...", "changes": [{field, from, to, node}]}
  {"type": "progress", "percent": N, "node": "...", "step": "M/N"}
  {"type": "result",   "image_url": "...", "metadata": {...}}
  {"type": "pipeline", "stages": [{name, status, output_url}], "current": N}
  {"type": "error",    "message": "...", "recoverable": bool}
```
