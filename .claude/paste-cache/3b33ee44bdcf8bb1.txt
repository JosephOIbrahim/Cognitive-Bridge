## Naming Convention: Memory Evolution Stages

Old (Pokémon) → New (VFX Pipeline):

| Old | New | Format | Description |
|-----|-----|--------|-------------|
| Charmander | **flat** | `memory.md` | Plain markdown. Session notes, decisions as text. |
| Charmeleon | **structured** | `memory.usd` | USD stage with typed prims. Sessions, decisions, parameters as scene graph data. |
| Charizard | **composed** | `memory.usd` + sublayers | USD with composition arcs. Scene memory sublayers project memory. Cross-shot queryable. |

The terms are self-describing. A TD reads "flat → structured → composed" and
immediately knows: flat text evolves into structured data evolves into composed
USD layers. No cultural reference needed.

```
I need you to create a main-thread tool executor for the SYNAPSE Houdini panel.

CONTEXT:
- Repo root: C:\Users\User\SYNAPSE
- The panel runs inside Houdini. hou.* calls MUST happen on the main thread.
- The Claude API worker runs on a QThread and cannot call hou.* directly.
- We need a Qt signal/slot bridge: worker emits signal → executor runs on main thread.
- python/synapse/panel/tool_bridge.py (already created) provides:
    get_tool_dispatch(name) → (command_type, payload_builder) or None
- python/synapse/server/handlers.py provides:
    SynapseHandler class with .handle(SynapseCommand) → SynapseResponse
- python/synapse/core/protocol.py provides:
    SynapseCommand(type, id, payload, sequence, timestamp)
    SynapseResponse(id, success, data, error)

YOUR TASK:
Create python/synapse/panel/tool_executor.py

REQUIREMENTS:

1. Class ToolExecutor(QtCore.QObject) — lives on the main thread (created by panel).

2. A ToolRequest class with fields:
   - tool_use_id: str (from Anthropic API tool_use block)
   - tool_name: str
   - tool_input: dict
   - result: Any (set by executor)
   - error: str or None (set by executor)
   - done: threading.Event() (set by executor when complete)

   The worker thread creates a ToolRequest, emits a signal, then calls
   request.done.wait(timeout=30.0) to block until the main thread finishes.

3. Slot execute_tool(self, request: ToolRequest):
   Decorated with @QtCore.Slot(object)
   This runs on the main thread (via Qt's AutoConnection from QThread signal).

   Steps:
   a) Call get_tool_dispatch(request.tool_name) to get (cmd_type, payload_builder)
   b) Build payload: payload = payload_builder(request.tool_input)
   c) Create SynapseCommand(type=cmd_type, id="panel-{name}-{timestamp}", payload=payload)
   d) Call self._handler.handle(command) → SynapseResponse
   e) If response.success: set request.result = response.data
      If not: set request.error = response.error
   f) ALWAYS call request.done.set() in a finally block

4. Lazy-load SynapseHandler in _get_handler(). Don't import at module level
   because hou may not be available yet. Cache after first successful import.
   If import fails, set request.error and return.

5. Handle exceptions gracefully. Log with logging module. Never let an
   exception escape without calling request.done.set() — the worker thread
   would hang forever.

6. Import Qt from PySide6 with PySide2 fallback (try/except pattern).
   Import threading for Event.

VERIFY:
- Read python/synapse/panel/tool_bridge.py to see get_tool_dispatch API
- Read python/synapse/server/handlers.py lines 217-317 to see SynapseHandler.handle()
- Read python/synapse/core/protocol.py lines 196-276 to see SynapseCommand/SynapseResponse
- Run: python -c "from synapse.panel.tool_executor import ToolExecutor, ToolRequest; print('Import OK')"
  (This will work outside Houdini since hou import is lazy)

DO NOT modify any existing files. Only create python/synapse/panel/tool_executor.py
```

- The worker runs on a QThread. It CANNOT call hou.* directly.
- Communication with main thread is via: emit signal with ToolRequest, then
  call request.done.wait(timeout=30) to block until executor completes.

YOUR TASK:
Create python/synapse/panel/claude_worker.py

This replaces the simple streaming worker in the panel with a full
tool-use conversation loop.

REQUIREMENTS:

1. Class ClaudeWorker(QThread) with signals:
   - token_received(str)     — text tokens for streaming display
   - stream_done()           — conversation complete
   - stream_error(str)       — error message
   - tool_requested(object)  — emits ToolRequest for main-thread execution
   - tool_status(str, str)   — (tool_name, status) where status is "running"/"done"/"error"

2. Constructor: __init__(self, messages, system_prompt="", parent=None)
   - Copy messages list (we'll mutate during tool loop)
   - Load tools via get_anthropic_tools()
   - Store abort flag

3. Method abort(self) — sets self._abort = True

4. Method run(self) — entry point:
   - Get API key from os.environ["ANTHROPIC_API_KEY"]
   - Call _conversation_loop(api_key)
   - Emit stream_done on success, stream_error on exception

5. Method _conversation_loop(self, api_key):
   THE CORE LOOP. Repeats until stop_reason != "tool_use" or max 25 iterations:

   a) Call _stream_request(api_key) → (stop_reason, content_blocks)
   b) If stop_reason == "tool_use":
      - Append {"role": "assistant", "content": content_blocks} to messages
      - For each tool_use block in content_blocks:
        * Create ToolRequest from block's id, name, input
        * Emit tool_status(name, "running")
        * Emit tool_requested(request)
        * Call request.done.wait(timeout=30.0)
        * If timed out: set request.error = "timed out"
        * Emit tool_status(name, "done" or "error")
        * Build tool_result dict: {type, tool_use_id, content, is_error}
        * Content should be JSON string if result is dict, else str
      - Append {"role": "user", "content": [tool_result_1, tool_result_2, ...]}
      - Continue loop (make another API call)
   c) If stop_reason is "end_turn" or "max_tokens": return (done)

6. Method _stream_request(self, api_key) → (stop_reason, content_blocks):
   Makes ONE streaming API call. Returns all content blocks accumulated.

   - Build request body with model="claude-sonnet-4-20250514", max_tokens=4096,
     stream=True, messages=self._messages, tools=self._tools
   - If self._system: add "system" field
   - Use http.client.HTTPSConnection (stdlib, no dependencies)
   - POST to api.anthropic.com /v1/messages with headers:
     Content-Type: application/json
     x-api-key: {api_key}
     anthropic-version: 2023-06-01
   - Parse SSE stream. Track state:
     * content_blocks: list accumulating all blocks
     * current_block: the block being built (text or tool_use)
     * current_text: accumulator for text content or JSON input
     * stop_reason: from message_delta event

   - SSE event handling:
     "content_block_start" → start new block (text or tool_use)
       For tool_use: capture id and name from content_block
     "content_block_delta" →
       text_delta: emit token_received, append to current text block
       input_json_delta: append partial_json to current_text (tool input accumulator)
     "content_block_stop" → finalize block:
       For tool_use: parse accumulated current_text as JSON → block["input"]
       Append to content_blocks
     "message_delta" → capture stop_reason

   - Return (stop_reason, content_blocks)

7. Method get_messages(self) → list:
   Returns copy of current messages (for panel to sync history after tool loops).

8. Use timeout=60 on HTTPSConnection (tool-use responses take longer).

9. Check self._abort at every loop iteration and in the SSE read loop.

IMPORTANT DETAILS:
- The Anthropic streaming format for tool_use accumulates the input JSON
  across multiple "input_json_delta" events. You must concatenate all
  partial_json strings, then JSON.parse the full string at content_block_stop.
- Multiple tool_use blocks can appear in a single response (parallel tool use).
  Process ALL of them before sending tool_results back.
- tool_result messages go in the "user" role, not "assistant".
- The tool_results for multiple tools go in a SINGLE user message as a list.

VERIFY:
- Read python/synapse/panel/tool_bridge.py to see get_anthropic_tools() output format
- Read python/synapse/panel/tool_executor.py to see ToolRequest class fields
- Run: python -c "from synapse.panel.claude_worker import ClaudeWorker; print('Import OK')"

DO NOT modify any existing files. Only create python/synapse/panel/claude_worker.py
```
