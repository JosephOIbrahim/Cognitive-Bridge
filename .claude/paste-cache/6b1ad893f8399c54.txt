## 0.4 — Standardize output schema
Create or update the chunk output schema to include these fields.
Find where chunks are currently defined and extend:

```python
# Target chunk schema
CHUNK_SCHEMA = {
    # Content
    "id": str,              # unique chunk ID (source_id + sequence)
    "content": str,          # the actual text content
    "code_blocks": list,     # extracted VEX code snippets (separate field)

    # Classification
    "content_type": str,     # concept | pattern | reference | troubleshooting | discussion
    "difficulty": str,       # beginner | intermediate | advanced | expert
    "vex_context": list,     # [sop, dop, cop, chop, cvex, material, solver]

    # Metadata
    "source_id": str,        # maps to sources.yaml
    "source_url": str,       # direct URL to source
    "source_authority": float,  # 0.0-1.0
    "title": str,            # human-readable chunk title
    "section": str,          # section within source (e.g., "JoyOfVex Day 7")

    # VEX-specific
    "functions_referenced": list,  # ["pcopen", "pcfind", "pcclose"]
    "houdini_version_min": str,    # minimum Houdini version
    "houdini_version_notes": str,  # deprecation or behavior change notes
    "prerequisites": list,         # chunk IDs this depends on

    # Pipeline
    "created_at": str,       # ISO timestamp
    "pipeline_version": str, # pipeline version that generated this
    "checksum": str,         # content hash for dedup detection
}
```

Don't break existing functionality. Add new fields with sensible defaults
so old chunks still work. Make the schema importable from a central location.

## 1.1 — cgwiki Scraper

1. Fetches all VEX-related pages from tokeru.com/cgwiki:
   - JoyOfVex01 through JoyOfVex20 (the TEXT versions, not YouTube)
   - HoudiniVex (the main VEX tips page)

2. Extracts:
   - Prose content (explanations, tips)

   - Code is often inline, not in fenced blocks
   - Uses `...` to indicate omitted code
   - GIF/image references should become text descriptions
   - "prev/this/next" navigation at page bottom should be stripped
4. Outputs to `output/cgwiki/` in the same chunk format as existing pipeline
5. Respects rate limiting (1 request/second minimum)
6. Is idempotent (can re-run, overwrites cleanly)
7. Tags every chunk with source_id: "cgwiki-vex"

Page list to scrape (at minimum):
- https://tokeru.com/cgwiki/JoyOfVex.html (index)
- https://tokeru.com/cgwiki/JoyOfVex01.html through JoyOfVex20.html
- https://tokeru.com/cgwiki/HoudiniVex.html

Use requests + BeautifulSoup. Don't use Selenium/Playwright.

## 1.2 — SideFX VEX Reference Scraper

Create `scripts/scrapers/scrape_sidefx_vex.py` that:

1. Fetches the VEX function reference from SideFX docs
2. Creates ONE chunk per function with:
   - Function name and signature
   - Description
   - Parameters with types
   - Return type
   - Example code (if provided)
   - Context availability (which VEX contexts support this function)
   - Related functions
3. Tags: content_type="reference", source_id="sidefx-vex-reference"
4. Outputs to `output/sidefx_reference/`

Target URL pattern:
https://www.sidefx.com/docs/houdini/vex/functions/

Note: SideFX docs may have anti-scraping measures.
Include a User-Agent header, respect robots.txt, rate limit to 1 req/2sec.
If scraping is blocked, create an alternative approach:
- Document the manual download process
- Write a parser that works on locally saved HTML files
- Create a config entry pointing to local docs path

## 1.3 — Local Skill Ingester

Create `scripts/ingest_local.py` that:

1. Reads markdown files from a local directory (configurable path)
2. Parses markdown into chunks at heading boundaries
3. Extracts VEX code blocks with language detection
4. First target: the vex-pattern-library skill files
5. Tags with source_id from config
6. Outputs alongside other sources

## 1.4 — Unified Merge Script

5. Flags near-duplicate chunks (>0.9 cosine similarity on content)
   - Use a simple approach: TF-IDF or MinHash, not heavy embeddings
6. Outputs a manifest file listing all chunks with metadata

### PHASE 2: Harden the Soil (Quality & Metadata)

```
Read docs/ANALYSIS.md and the current codebase. We're adding quality
gates and metadata enrichment to the pipeline.

## 2.1 — VEX Code Extractor & Validator

Create `scripts/enrichment/vex_extractor.py` that:

1. Takes a chunk and extracts all VEX code blocks into the
   `code_blocks` field (list of dicts with code + line context)
2. For each code block:
   - Extract all VEX function names (regex: word followed by `(`)
   - Populate `functions_referenced` on the parent chunk
   - Check for common VEX syntax issues:
     * Missing semicolons
     * Unclosed braces/parens
     * Using deprecated `@opinput1_` syntax
     * Using global variables directly (flagged as warning)
   - Flag but don't reject — add a `validation_warnings` field
3. Cross-reference extracted functions against the SideFX reference
   chunks (if they exist in the corpus)

## 2.2 — Auto-Tagger

Create `scripts/enrichment/auto_tagger.py` that:

1. Applies rule-based tagging to chunks missing metadata:

   **Difficulty detection:**
   - Contains only `@P`, `@Cd`, `@N`, basic arithmetic → beginner
   - Contains `pcopen`, `pcfind`, foreach loops → intermediate
   - Contains `getbbox_size`, matrix ops, intrinsics → advanced
   - Contains solver references, compile blocks, threading → expert

   **Content type detection:**
   - Has "how to" or step-by-step structure → pattern
   - Has function signature + params → reference
   - Has "error", "fix", "why does" → troubleshooting
   - Has "what is", "introduction", "overview" → concept
   - Has forum-style Q&A → discussion

   **VEX context detection:**
   - Contains `@Frame`, `@Time` + particle refs → dop
   - Contains `@voxelsize`, volume functions → volume
   - Contains `@uv`, shader functions → material/cvex
   - Default: sop

   **Houdini version detection:**
   - References to `chramp` clamping behavior → "19.5+"
   - References to `@opinput1_` → "pre-17.0"
   - References to `osd_limit` → "21.0+"

2. Never overwrite existing tags — only fill gaps
3. Log all tagging decisions for review

## 2.3 — Prerequisites Linker

Create `scripts/enrichment/prereq_linker.py` that:

1. Builds a concept graph from chunk titles and content
2. For JoyOfVex chunks: JoV Day N depends on Day 1..N-1
3. For function reference chunks: link to concept chunks that explain them
4. For pattern chunks: link to the functions they use
5. Output: each chunk gets a `prerequisites` list of chunk IDs
6. Store graph as `output/corpus/prereq_graph.json`

## 2.4 — Deduplication Report

Create `scripts/quality/dedup_report.py` that:

1. Compares all chunks in merged corpus
2. Uses MinHash (datasketch library) for approximate similarity
3. Flags pairs with >0.85 Jaccard similarity
4. For each pair, recommends:
   - KEEP: higher authority source
   - LINK: lower authority source references higher
   - MERGE: combine if complementary
5. Outputs `output/corpus/dedup_report.json`
6. Does NOT auto-delete — human review required

## 2.5 — Pipeline Orchestrator

Create `scripts/run_pipeline.py` that:

1. Runs all stages in order with a single command
2. Supports `--source` flag to process only one source
3. Supports `--stage` flag to run from a specific stage
4. Supports `--dry-run` to show what would happen
5. Logs to `logs/pipeline_YYYYMMDD_HHMMSS.log`
6. Reports timing per stage
7. Exits cleanly on error with state saved

Usage:
  python scripts/run_pipeline.py                    # full run
  python scripts/run_pipeline.py --source cgwiki    # one source
  python scripts/run_pipeline.py --stage enrich     # from enrichment
  python scripts/run_pipeline.py --dry-run           # preview
```

### PHASE 3: Harvest Season (Retrieval & Evaluation)

```
Read docs/ANALYSIS.md and the current codebase. We're optimizing
retrieval quality and adding evaluation.

## 3.1 — Hybrid Search Index Builder

Create `scripts/retrieval/build_index.py` that:

1. Builds two complementary indices from the corpus:

   **Keyword index** (for exact function name matching):
   - BM25 index over chunk content
   - Boost field: `functions_referenced` (exact match critical)
   - Use `rank_bm25` or `whoosh` library

   **Semantic index** (for concept matching):
   - Embed chunks using a code-aware model
   - Recommended: `Alibaba-NLP/gte-large-en-v1.5` or
     `BAAI/bge-large-en-v1.5` (both handle code reasonably)
   - Store in ChromaDB or FAISS (whichever Synapse already uses)

2. Query interface that combines both:
   ```python
   def search(query: str, top_k=10, difficulty=None, context=None):
       keyword_results = bm25_search(query, top_k=top_k*2)
       semantic_results = embed_search(query, top_k=top_k*2)
       combined = reciprocal_rank_fusion(keyword_results, semantic_results)
       if difficulty:
           combined = filter_by_difficulty(combined, difficulty)
       if context:
           combined = filter_by_context(combined, context)
       return combined[:top_k]
   ```

## 3.2 — VEX Query Expander

Create `scripts/retrieval/query_expand.py` that:

1. Maintains a VEX-specific synonym/concept map:
   ```yaml
   expansions:
     "scatter points": ["point distribution", "random placement", "seed"]
     "color": ["@Cd", "colour", "RGB", "chromatic"]
     "move points": ["@P", "displacement", "deformation", "position"]
     "find nearest": ["pcfind", "pcopen", "nearpoint", "proximity"]
     "loop": ["foreach", "for loop", "iteration", "while"]
     "random": ["rand", "noise", "seed", "stochastic"]
     "speed": ["performance", "cook time", "optimization", "PERF"]
     "array": ["list", "resize", "append", "push"]
     "matrix": ["transform", "rotate", "scale", "orient", "quaternion"]
     "group": ["pointgroup", "primgroup", "membership", "selection"]
   ```

2. Expands user queries before search
3. Strips Houdini jargon into searchable terms

## 3.3 — Evaluation Harness

Create `scripts/eval/run_eval.py` with:

1. A test suite of VEX queries with expected retrieval targets:
   ```yaml
   test_queries:
     - query: "How do I color points based on distance?"
       expected_chunks: ["jov-day-02", "jov-day-03"]
       expected_functions: ["length", "fit"]
       difficulty: beginner

     - query: "Point cloud averaging for smoothing"
       expected_chunks: ["jov-day-20", "pattern-pcfilter"]
       expected_functions: ["pcopen", "pcfilter", "pcclose"]
       difficulty: intermediate

     - query: "How do packed primitive transforms work?"
       expected_chunks: ["jov-day-18", "ref-intrinsic"]
       expected_functions: ["setprimintrinsic", "packedtransform"]
       difficulty: advanced

     - query: "My wrangle is slow on 1M points"
       expected_chunks: ["pattern-performance", "troubleshoot-cook-time"]
       expected_functions: []
       difficulty: intermediate
       content_type: troubleshooting

     - query: "What does pcopen do?"
       expected_chunks: ["ref-pcopen"]
       expected_functions: ["pcopen"]
       content_type: reference
   ```

2. Metrics:
   - Recall@K: are expected chunks in top K?
   - MRR: mean reciprocal rank of first expected chunk
   - Function precision: do retrieved chunks mention expected functions?

3. Reports results as a table + saves to `output/eval/results.json`
4. Tracks over time so you can see if changes improve retrieval
