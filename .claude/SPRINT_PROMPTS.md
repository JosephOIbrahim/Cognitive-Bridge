# SYNAPSE Sprint Prompt Playbook

> **How to use:** Paste this entire document into Claude Code. It will
> auto-detect which phase is next and execute only that one phase.

## Execution Directive

Read this playbook. Do NOT execute all phases.

1. Run the Sprint Orchestrator checks from CLAUDE.md to determine which sprint is active
2. Check which gate files already exist to determine which phase is NEXT
3. Execute ONLY that single phase
4. Run the verification commands for that phase
5. Stop and report:
   - What you completed
   - Which gate files now exist
   - What the NEXT phase is
   - Any issues or blockers encountered

Do not continue to the next phase. One phase per session.

### Phase Detection Logic

```bash
# Check what exists — this determines which phase is next
ls synapse/mcp/__init__.py 2>/dev/null          || echo "NEXT: Prompt 0 (scaffold)"
ls docs/tops/PARKING_SNAPSHOT.md 2>/dev/null     || echo "NEXT: Prompt 0 (park TOPS)"
ls synapse/mcp/protocol.py 2>/dev/null           || echo "NEXT: Prompt 1a (protocol)"
ls synapse/mcp/tools.py 2>/dev/null              || echo "NEXT: Prompt 1b (tool registry)"
ls synapse/mcp/server.py 2>/dev/null             || echo "NEXT: Prompt 1c (server endpoint)"
ls synapse/mcp/resources.py 2>/dev/null          || echo "NEXT: Prompt 2a (resources)"
ls docs/mcp/SETUP.md 2>/dev/null                 || echo "NEXT: Prompt 2b (prompts + SETUP)"
# MCP complete — check TOPS
grep -q "tops_get_work_items" synapse/mcp/tools.py 2>/dev/null || echo "NEXT: Prompt T1 (read-only TOPS)"
grep -q "tops_cook_node" synapse/mcp/tools.py 2>/dev/null      || echo "NEXT: Prompt T2 (mutation TOPS)"
grep -q "tops_configure_scheduler" synapse/mcp/tools.py 2>/dev/null || echo "NEXT: Prompt T3 (scheduler)"
```

Pick the FIRST "NEXT" line that prints. That's your phase. Execute only that phase below.

## MCP Sprint — Phase 1 (MVP)

### Prompt 1a — Protocol Foundation

```
Read CLAUDE.md and docs/mcp/SYNAPSE_MCP_SPRINT.md.

Implement the MCP protocol foundation:
1. synapse/mcp/protocol.py — JSON-RPC 2.0 utilities: request parsing, response building, error codes (standard + custom SYNAPSE codes), content-type handling
2. synapse/mcp/types.py — Type definitions and schemas for MCP messages
3. synapse/mcp/session.py — Session manager: create session on initialize, track by Mcp-Session-Id header, destroy on disconnect

Write tests for all three modules in tests/test_mcp_protocol.py. The tests should verify:
- JSON-RPC request parsing (valid, malformed, missing fields)
- Error code formatting
- Session create/track/destroy lifecycle
- Session ID header handling

Run the tests before finishing.
```

**Verify:**
```bash
python -m pytest tests/test_mcp_protocol.py -v
```

### Prompt 1b — Tool Registry & Dispatch

```
Read CLAUDE.md and docs/mcp/SYNAPSE_MCP_SPRINT.md.

Building on the protocol foundation from last session, implement:
1. synapse/mcp/tools.py — Tool registry that maps ALL existing SYNAPSE handlers to MCP tool definitions. Each tool needs inputSchema (JSON Schema) and annotations (readOnlyHint, destructiveHint, idempotentHint, openWorldHint). Include the dispatch_tool bridge function that routes tools/call to existing handlers through safety middleware.

The tool registry should be generated by introspecting handlers.py — don't hardcode 39 tool definitions manually if you can derive them from the handler registry.

Add tests to test_mcp_protocol.py:
- tools/list returns all registered tools with valid schemas
- tools/call dispatches to the correct handler
- tools/call with unknown tool returns -32602
- tools/call error from handler returns isError: true

Run ALL tests (not just new ones) before finishing.
```

**Verify:**
```bash
python -m pytest tests/test_mcp_protocol.py -v
python -m pytest tests/ -v --tb=short  # full suite, nothing broken
```

### Prompt 1c — Server Endpoint & Integration

```
Read CLAUDE.md and docs/mcp/SYNAPSE_MCP_SPRINT.md.

This is the session that connects everything. Implement:
1. synapse/mcp/server.py — The /mcp endpoint handler on hwebserver. This is the JSON-RPC router that:
   - Accepts POST /mcp with JSON-RPC requests
   - Routes initialize → session creation + capabilities response
   - Routes notifications/initialized → 202 Accepted
   - Routes tools/list → tool registry
   - Routes tools/call → dispatch bridge → existing handlers
   - Routes ping → pong
   - Handles Mcp-Session-Id headers on all requests after initialize
   - Returns proper error responses for unknown methods

2. Wire the endpoint into hwebserver_adapter.py (or whatever the appropriate registration point is)

Add integration tests to test_mcp_protocol.py:
- Full initialize handshake (initialize → initialized notification → tools/list)
- Session header validation (missing, invalid, expired)
- End-to-end tool call through the full stack (with mocked handler)

Evaluate whether the Python MCP SDK (pip install mcp) integrates cleanly with hwebserver. If it does, use it. If not, the manual implementation you just built is the path.

Run full test suite before finishing.
```

**Verify:**
```bash
python -m pytest tests/test_mcp_protocol.py -v
python -m pytest tests/ -v --tb=short
python -m mypy python/synapse/ --config-file pyproject.toml
```

## Notes

- **Paste this entire document each session.** Phase detection runs automatically — you don't pick which prompt to run.
- **One phase per session.** Claude Code executes one phase, verifies, stops. Next session, paste again, it picks up where it left off.
- **If tests fail,** fix in the same session before reporting completion. A phase isn't done until verification passes.
- **The Sprint Orchestrator auto-detects.** You never need to edit CLAUDE.md to switch sprints.
- **Phase 3 (MCP polish) is optional.** The TOPS sprint activates as soon as Phase 1+2 gate files exist, regardless of Phase 3 status.
- **If Claude Code gets stuck**, narrow the scope: "Just implement tops_cook_node handler in handlers.py and its test. Nothing else."
